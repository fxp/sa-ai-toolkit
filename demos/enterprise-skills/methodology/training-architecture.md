# 培训架构设计原理

> 从九洲电器3.5小时培训实战提炼的方法论。

## 核心理念

### 企业AI落地的5层需求金字塔

```
          ┌─────────────┐
          │  决策智能     │  ← 跨部门Agent协调、战略分析
         ─┤  (Layer 5)   ├─
        ┌─┴─────────────┴─┐
        │  流程自动化       │  ← 审批工作流、生产排程优化
       ─┤  (Layer 4)       ├─
      ┌─┴─────────────────┴─┐
      │  专业判断辅助         │  ← 质检AI、合同风险、标书审查
     ─┤  (Layer 3)           ├─
    ┌─┴─────────────────────┴─┐
    │  信息检索与整理           │  ← 知识库RAG、文档一致性、纪要
   ─┤  (Layer 2)               ├─
  ┌─┴─────────────────────────┴─┐
  │  基础认知与体验               │  ← AI能力边界、Prompt工程
  │  (Layer 1)                   │
  └───────────────────────────────┘
```

**关键：每家企业都从Layer 1-2开始，但决策层关心Layer 4-5的故事。**

### 双引擎架构（最重要的技术方法论）

```
硬性规则 → 代码执行（准确率100%，毫秒级）
模糊判断 → 大模型辅助（效率提升10x，秒级）
两者结合 = 可靠的AI应用
```

这个架构贯穿B1/B2/B3/D1所有Demo，是培训中反复强调的核心概念。

## 培训时间结构

### 3.5小时标准版（上午领导+下午技术）

```
上午（1.5h，面向60+中层以上）：
  市场趋势 → 战略价值 → 标杆案例 → 行动呼吁
  风格：宏观、鼓舞、决策视角

下午（3.5h，面向200-300人技术+业务）：
  [T+0:00] 开场Hook（5min）
  [T+0:05] 第一讲：趋势（40min）——四阶段+三重构+角色演进
  [T+0:45] 第二讲：场景（45min）——行业场景全景+现场Demo
  [T+1:30] 休息（10min）
  [T+1:40] 第三讲：前沿（40min）——多Agent辩论（学员互动⭐）
  [T+2:20] 第四讲：案例（25min）——深度案例Demo
  [T+2:45] 第五讲：Workshop（45min）——学员动手实操
  [T+3:30] 总结+Q&A（15min）——行动卡片
```

### 2小时精简版

```
  [T+0:00] 开场+趋势（20min）
  [T+0:20] 场景Demo（40min）——P0 Demo
  [T+1:00] 休息（10min）
  [T+1:10] 前沿+互动（30min）——多Agent辩论
  [T+1:40] 行动建议（20min）
```

### 1小时管理层版

```
  [T+0:00] 开场（5min）
  [T+0:05] 趋势+价值（15min）

  [T+0:40] 行动建议+ROI（15min）
  [T+0:55] Q&A（5min）
```

## 实验设计原则

| 原则 | 说明 |
|------|------|
| **做中学** | 每个实验有学员亲手操作的环节 |
| **由浅入深** | 问答→配置→编排，逐步升级 |
| **即用即走** | 结果是学员能带回去直接用的 |
| **失败有价值** | AI输出不好→当众分析原因→踩坑教育 |

## 受众分层策略

### 决策层（董事长/副总/部长）
- 关注：ROI、竞争优势、风险
- Demo选择：E1多Agent辩论 + A1三级能力 + 1个P0行业Demo
- 话术：用"投资回报""竞争壁垒""降本增效"语言

### 业务人员（市场/销售/采购/质量）
- 关注：能不能解决我的日常痛苦
- Demo选择：B系列（文档智能）+ D系列（专业判断）
- 话术：用他们自己的"原话"引入（"你们是不是也遇到过..."）

### 技术人员（IT/研发/软件团队）
- 关注：怎么实现、什么架构、能不能落地
- Demo选择：E5编程助手 + C系列（知识库）+ 双引擎架构讲解
- 话术：用架构图、代码片段、API调用

## 关键台词模板

### 开场Hook
> "如果你们每个部门都有一个不睡觉、不请假、不抱怨的AI员工，公司会变成什么样？"

### 痛点共鸣引入Demo
> "你们{部门}是不是也遇到过这种情况——{用企业原话描述痛点}？
>  我们来看看AI怎么解决这个问题……"

### Demo失败应急
> "大家看到了，AI在这个任务上并不完美——这恰恰说明了我们的核心方法论：
>  硬性规则靠代码（100%准确），模糊判断靠模型。两个引擎配合才可靠。"

### 收尾行动
> "今天看了这么多Demo，回去之后最重要的三件事：
>  第一，选一个痛点最痛的场景，下周就开始试；
>  第二，组一个3-5人的'红队'，用AI做同样的业务，跟不用AI的对标；
>  第三，别等完美方案，先跑起来再优化。"
